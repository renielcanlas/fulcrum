# Conceptual architecture

One web application with a relational governed data store, object evidence store, search/retrieval index, job queue, deterministic scoring/configuration module, AI gateway, workflow/authorization module, audit ledger, and operator UI/API. Workers run agent tasks and integration sync jobs through the orchestrator; agents and external adapters can read scoped context and propose changes, but authoritative writes occur through validated application commands. Architecture principles are defined in [architecture-principles.md](architecture-principles.md).

Flow: intake → workflow case → evidence ingestion → extraction/policy retrieval → structured observations → scoring → analyst review → challenge → committee package → human decision → audit/notifications. A separate integration path connects the web app to Jira through the server-side OAuth adapter and sync worker; it never makes Jira authoritative for risk. The AI gateway hides provider SDKs and records model metadata. Adapters are isolated behind interfaces for Jira, repositories, identity, notifications, and observability.

Trust boundaries: user/browser, application API, evidence/parser sandbox, retrieval index, model providers, and external integrations. Authorization is enforced at the application/tool boundary, never delegated to a model. See ADR-000 and [security model](../07-governance/security-model.md).

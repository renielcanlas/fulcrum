# Security model

Threats include unauthorized case access, malicious documents and prompt injection, data exfiltration through tools/models, fabricated citations, poisoned retrieval, privilege escalation, tampered audit, provider outage, OAuth state/code attacks, token theft, excessive Jira scopes, and cross-tenant sync. Controls: SSO/RBAC and least privilege; application-enforced authorization; encrypted transport/storage; Azure managed identity and Key Vault where available; server-side OAuth callback and encrypted token vault; random one-time state bound to session; exact redirect URI; token redaction; malware/parser sandbox; Azure Document Intelligence extraction isolation; content/instruction separation; allowlisted tools and egress; DLP/redaction policy; immutable audit; model/provider access policy; rate limits; validation and human gates; backups and incident response. Synthetic data is mandatory until data handling is approved.

Azure AI Foundry and Document Intelligence endpoints, deployment names, API versions, and credentials are environment configuration and never client-visible. Logs record provider/deployment metadata, status, timing, IDs, hashes, and redacted error classes without raw document text, secrets, or unrestricted prompts. Document extraction output is untrusted evidence until validated and reviewed; Document Intelligence cannot score risk or make a decision.

Security acceptance tests must include cross-role access denial, prompt injection, malicious file handling, citation grounding, tool authorization, audit tamper detection, secret exposure, OAuth state fixation/replay, callback CSRF, redirect mismatch, token leakage, revoked-consent handling, scope enforcement, cross-tenant isolation, and fail-closed workflow transitions.
